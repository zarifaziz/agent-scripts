# Clean Up Storage

Free disk space by deleting only things that rebuild themselves. Measure first, delete what is deterministically reproducible, ask before anything that could hold work.

## Method

1. `df -h /` — record free space.
2. Scan (below) to find where the space actually went. Do not trust the sizes in this file; they age fast.
3. Delete the safe tier without asking.
4. Ask before the judgement tier.
5. `df -h /` again and report the gain.

The tiers matter more than the numbers. Sizes here are from a scan on 2026-08-25 (460 GB disk, 210 GB free after cleaning) and are examples, not expectations.

## Scan

```bash
df -h /

# Where the space went, top level
du -sh ~/Library/Application\ Support ~/Library/Caches ~/Coding ~/.cache ~/.local 2>/dev/null | sort -rh

# Drill into each
du -sh ~/Library/Application\ Support/* 2>/dev/null | sort -rh | head -12
du -sh ~/Library/Caches/* 2>/dev/null | sort -rh | head -12
du -sh ~/.cache/* 2>/dev/null | sort -rh | head -10
du -sh ~/Coding/* 2>/dev/null | sort -rh | head -12

# Dependency dirs across all projects
find ~/Coding -maxdepth 5 \( -name target -o -name build -o -name node_modules -o -name .venv \) \
  -type d -prune 2>/dev/null | xargs -I{} du -sh {} 2>/dev/null | sort -rh | head -15
```

## Safe tier — delete without asking

Everything here is regenerated by a command the user already runs.

```bash
# uv Python cache. Use prune, NOT rm -rf: uv hardlinks cache files into every
# .venv, so a blind delete frees little and forces a full re-download.
uv cache prune

# Homebrew old formula versions
brew cleanup --prune=0

# Model and browser download caches
rm -rf ~/.cache/huggingface ~/.cache/puppeteer

# Electron app caches (these are caches, not the Partitions dir — see below)
rm -rf ~/Library/Caches/com.spotify.client/*
rm -rf ~/Library/Caches/com.todesktop.230313mzl4w4u92.ShipIt   # Cursor updater leftovers

# Other rebuildables that show up in scans
rm -rf ~/Library/Caches/pypoetry ~/Library/Caches/go-build ~/Library/Caches/node-gyp
```

Playwright browsers (`~/Library/Caches/ms-playwright`) are safe too, but only clear them if the user is not mid-way through browser testing — reinstall is `npx playwright install`.

## Judgement tier — ask first

**Claude Desktop `vm_bundles`** — the sandbox VM images, often the single biggest item on the disk. Deleting them is safe but the next sandboxed run re-downloads several GB. Requires quitting Claude Desktop.

```bash
osascript -e 'quit app "Claude"' && sleep 4
rm -rf ~/Library/Application\ Support/Claude/vm_bundles \
       ~/Library/Application\ Support/Claude/Cache
```

Never touch `~/Library/Application Support/Claude/claude-code*` or `local-agent-mode-sessions` — that is session history.

**Notion offline cache** — re-downloads on relaunch. Requires quitting Notion. Delete `Partitions` only; `notion.db` is the local index.

```bash
osascript -e 'quit app "Notion"' && sleep 4
rm -rf ~/Library/Application\ Support/Notion/Partitions
```

**Stale `node_modules` and `.venv`** — the ones under `~/Coding/Playground` and other finished experiments are usually dead weight. Active projects (metarepo, auralis-app) rebuild fine but cost the user a slow `uv sync` / `npm install`, so name the specific dirs and let them choose.

**Google Chrome** — `~/Library/Application Support/Google` and `~/Library/Caches/Google` are typically 10 GB+ combined. Do not delete from the CLI, it corrupts profiles. Tell the user: Chrome Settings → Privacy → Clear browsing data → Cached images and files.

## Never touch

- **Git worktrees** — `~/Coding/auralis-app/.worktrees` and any other `.worktrees` dir. They may hold uncommitted work. To clean these, use the dedicated worktree-pruning skill, which checks merge status first.
- **`~/.local/share/nvim`** — active config and plugins.
- **Anything under a repo that is not a build artifact** — if in doubt, do not.

## Notes on this machine

Current work is Peer AI (`~/Coding/metarepo`: Python services with per-service `.venv`, `frontend/peer-fe` with node_modules) and Auralis (`~/Coding/auralis-app`). Space concentrates in Python virtualenvs and node_modules rather than compiled artifacts.

There is no Rust or Flutter toolchain installed anymore, so `~/.cargo`, `~/.rustup`, `~/flutter`, `~/fvm`, and Cargo `target` dirs will not appear in scans. If a scan does turn them up, the setup has changed and this file needs updating.
